# 「세계를 잇는 여행」 제작기

> 초등학교 6학년 사회과(6-2 '지구촌 사람들') 다문화·세계지리 교육 웹게임을 만든 과정을 기록합니다.
> 이 문서의 모든 내용은 저장소의 실제 코드와 문서(README, docs/TRD.md, docs/QA_CHECKLIST.md, docs/ASSET_AUDIT.md)에서 확인한 사실만 담았습니다. 학생 반응이나 수업 적용 결과는 아직 측정한 적이 없어 싣지 않았습니다.

## 1. 어떤 게임인가요

학생이 로봇 비행기와 함께 다섯 대륙을 여행하며 각 지역의 생활 자료를 조사하고, 존중하는 대화를 연습하는 게임입니다. 플레이 전체가 **관찰 → 증거 찾기 → 가설 세우기 → 질문하기 → 경청하기 → 판단 수정하기**의 학습 순환을 따르도록 설계했습니다.

첫 방문 흐름은 타이틀 → 여행자 여권(별명·아바타 만들기) → 세계 항로 지도이며, 지도에서 다섯 대륙 미션을 자유로운 순서로 완료하면 대화 미션과 최종 인증 화면이 열립니다.

## 2. 기획 의도 — 성취기준에서 출발했습니다

2022 개정 교육과정 사회과 성취기준 5종을 먼저 정하고, 각 화면이 어느 성취기준을 다루는지 역으로 배치했습니다.

| 성취기준 | 게임 연계 |
| -- | -- |
| [6사09-01] 공간 자료의 특징과 위치 표현 | 세계 항로 지도 탐색 |
| [6사09-02] 주요 대륙·대양과 국가 위치 | 대륙별 여행 경로와 지역 탐색 |
| [6사10-01] 지형 경관과 다양한 삶의 모습 | 지역 환경과 생활문화 연결 (대륙 미션) |
| [6사10-02] 기후 환경과 인간 생활의 관계 | 기후·의식주·생활방식 탐구 |
| [6사12-02] 지구촌 문제와 지속 가능한 미래 | 오세아니아 환경·공동체 3턴 시뮬레이션 |

게임 한 번의 플레이가 성취기준을 완전히 달성하는 것은 아니며, 수업의 탐구·토론 활동과 함께 쓰는 보조 도구로 설계했습니다. 각 미션의 학습목표·성취기준 연결은 콘텐츠 파일(`public/content/v1/ko/*.json`)에 구조화해 기록했고, 테스트(`tests/content.test.ts`)가 학습목표가 비어 있지 않은지 자동으로 검사합니다.

## 3. 10페이지 구성

타이틀(1) — 세계 항로 지도(2) — 여행자 여권(3) — 아시아(4) — 유럽(5) — 아프리카(6) — 아메리카(7) — 오세아니아(8) — 다름을 잇는 대화(9) — 세계 연결 인증(10)의 10개 화면으로 구성했습니다. 대화 미션(9)은 다섯 대륙을 모두 완료해야 열리고, 인증(10)은 대화까지 마쳐야 열립니다. 이 잠금 상태는 저장값을 믿지 않고 라우터가 접근할 때마다 다시 계산합니다(`src/router.ts`의 `guard()`).

## 4. 상호작용 — "클릭 반복"을 피하려고 했습니다

미션마다 조작 방식이 학습 과제와 직접 대응하도록 서로 다른 상호작용을 구현했습니다. 아래는 모두 현재 코드에 실제로 들어 있는 것들입니다.

- **아시아 — 드래그 타임라인**: 다른 나라 어린이의 하루 자료를 관찰하고 타임라인에 배치한 뒤, 사실·해석·확인필요를 분류하고 존중 질문을 조립합니다.
- **유럽 — 경로 설계**: 자료를 읽고 목적이 다른 두 여행 경로를 설계해 비교합니다. 정답이 하나가 아니라 목적에 따라 달라집니다.
- **아프리카 — 리듬 시퀀서**: 8칸 리듬을 듣고 재구성하는 콜 앤 리스폰스입니다. 소리를 들을 수 없는 환경을 위해 시각 박자점을 함께 표시합니다.
- **아메리카 — 제약 일정 조립**: 필요와 선호를 분류하고, 제약 조건 안에서 함께 보내는 하루 일정을 조립해 대안과 비교합니다.
- **오세아니아 — 3턴 시뮬레이션**: 섬의 핫스폿을 조사하고 서로 다른 관점 카드를 들은 뒤, 환경·공동체 지표가 변하는 3턴 의사결정 시뮬레이션을 합니다.
- **대화 미션 — 분기 대화**: 인사 사례 매칭, 경청 연습, 공감 나침반 분기 대화로 이어집니다.

실패했을 때 벌점 대신 재도전 단서와 부분 점수를 주고, 판단을 수정할 기회로 이어지게 했습니다(최종점검 문서 docs/QA_CHECKLIST.md 3번 항목에서 확인).

## 5. 기술 구조 요약

- **스택**: Vite + TypeScript + Phaser 3 + 바닐라 DOM/CSS/SVG. React도 서버도 없습니다.
- **라우팅**: 해시 라우터가 10개 페이지를 lazy import로 나눠 불러옵니다. 앱 초기 JS는 20.40kB(gzip 7.56kB)이고, Phaser는 지도 화면에서만 lazy 청크(gzip 332.40kB)로 로드됩니다.
- **저장**: 서버 없이 `localStorage` 한 키에 저장합니다. 손상된 저장값은 백업 후 기본값으로 복구하고, 해금 상태는 항상 다시 계산합니다.
- **오디오**: 전역 AudioManager가 BGM 6곡을 crossfade로 전환하고, 같은 효과음의 중첩 재생을 차단합니다.
- **검증**: `npm run verify` 한 명령으로 TypeScript 타입 검사, Vitest 테스트, production 빌드를 모두 돌립니다.
- **네트워크**: 폰트·이미지·오디오가 전부 로컬 번들이라 런타임 외부 요청이 없습니다. 학교망의 CDN 차단에 걸릴 요소를 처음부터 만들지 않았습니다.

## 6. 에셋 파이프라인 이야기

이미지 원본은 AI로 생성한 PNG 182장이었습니다. 이 원본을 그대로 쓰면 수백 MiB가 되므로, 다음 원칙으로 파이프라인을 만들었습니다.

1. **원본은 절대 수정하지 않습니다.** 원본 PNG는 `assets/`, `background/`, `title/`, `3d assets/`에 그대로 보존하고, 픽셀이 완전히 같은 중복 23장만 `_unused/duplicates/`로 옮겨 보관했습니다.
2. **빌드 산출물만 변환합니다.** `npm run assets`(scripts/build-assets.mjs, sharp 사용)가 배경 1600px·캐릭터 512px·아이콘 256px 규격으로 WebP를 생성합니다. 결과는 WebP 47개, 총 3.797MiB입니다.
3. **코드는 파일 경로가 아니라 의미 ID로 참조합니다.** `src/content/asset-manifest.json`이 `bg.asia`, `plane.main` 같은 semantic ID와 원본 경로·라이선스·용도를 기록하고, 코드는 `assetUrl()`/`hasAsset()`으로만 접근합니다. 이미지가 없어도 화면이 깨지지 않고 대체 표현으로 넘어갑니다.

어떤 원본이 어디에 쓰였는지, 무엇이 미사용인지는 docs/ASSET_AUDIT.md에 전량 기록했습니다.

## 7. 문화적 안전장치

다문화 소재를 다루는 게임이라 내용 안전장치를 코드와 데이터 양쪽에 두었습니다.

- **단일 문화 단정 금지**: "이 나라 사람들은 모두 ~한다" 식 서술 대신 특정 인물의 사례로 표현하도록 콘텐츠를 작성했습니다.
- **모든 콘텐츠에 `needsReview: true`**: 배포 콘텐츠 7종 전부에 검토 필요 표시가 있고, 테스트가 이 플래그의 존재를 강제합니다. 교사 검수 전에는 공식 수업·공개 배포가 조건부라는 뜻입니다.
- **추정 배정 기록**: 인물 이미지에 국가 단서가 없는 경우, manifest의 note에 "추정"이라고 명시해 나중에 검토할 수 있게 남겼습니다.
- **콘텐츠 검증기**: `validateContentDocument()`가 HTML 삽입과 위험한 식별자를 거부해, 콘텐츠 JSON을 수정하다 실수해도 화면에 스크립트가 주입되지 않습니다.
