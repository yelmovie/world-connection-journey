## 1. 무엇을 만들었나

학생이 로봇 비행기와 함께 여섯 대륙을 여행하며 지역의 생활 자료를 조사하고, 존중하는 대화를 연습한 뒤 세계 친구 지구회의에서 공동약속을 만드는 게임이다. 플레이 전체가 **관찰 → 증거 찾기 → 가설 세우기 → 질문하기 → 경청하기 → 판단 수정하기**의 순환을 따르도록 설계했다.

흐름: 타이틀 → 여행자 여권(별명·아바타·비행기) → 세계 항로 지도 → 아시아·유럽·아프리카·아메리카·오세아니아(자유 순서) → 마지막 단계 「하나의 지구, 여섯 개의 신호」(인사·경청 → 환경 신호 → 연결 → 지구회의 → 약속) → 인증서.

성취기준은 2022 개정 사회과 5종([6사09-01]·[6사09-02]·[6사10-01]·[6사10-02]·[6사12-02])을 먼저 정하고 화면을 역으로 배치했다. 각 미션의 학습목표·활동·피드백은 콘텐츠 JSON(`public/content/v1/ko/*.json`)에 성취기준과 함께 구조화했고, 테스트가 학습목표가 비어 있지 않은지 자동 검사한다.

## 2. 기술 선택과 이유

| 영역 | 선택 | 이유 |
|---|---|---|
| 빌드 | Vite 7 + TypeScript 5 (strict) | 정적 배포, 빠른 HMR |
| 게임 캔버스 | Phaser 3, 세계지도에서만 동적 import | 지도 연출·비행기 트윈에만 필요. 초기 JS 청크 20KB(gzip 7.6KB), Phaser 청크는 지도 진입 때만 |
| UI | 바닐라 DOM + CSS + 인라인 SVG | 한글 텍스트·접근성·인쇄. 학습 텍스트를 이미지에 굽지 않음 |
| 오디오 | HTMLAudio(BGM 크로스페이드) + WebAudio(SFX·합성 타악기) | 아프리카 리듬 시퀀서의 정밀 스케줄링 |
| 저장 | localStorage 스키마 v1 | 서버 없음, 개인정보 최소화(별명만) |
| 폰트 | Jua·Pretendard woff2 셀프호스팅 | 학교망 외부 CDN 차단 대비, 런타임 외부 요청 0 |
| 오프라인 | 서비스워커 프리캐시 | 빌드 산출물 목록(precache-manifest.json)을 install 때 전부 캐시 → 방문 안 한 lazy 청크도 오프라인에서 열림 |

React를 쓰지 않은 건 화면 10개짜리 해시 라우팅 앱에서 상태 라이브러리보다 DOM 직접 조작이 인쇄·접근성·한글 줄바꿈 제어에 더 단순했기 때문이다.

## 3. 구조 — 책임 분리

```
src/core/    EventBus(타입 지정 이벤트 단일 소스), SaveRepository, AudioManager,
             ContentRepository, assets(매니페스트), stamps(도장 규칙 한 곳)
src/ui/      chrome(상단바·설정), modal, toast, guide(마스코트 말풍선), dnd(집기-놓기),
             fitText, swipe, timerPool, escape … 공용 부품
src/pages/   화면 10개 — 라우터가 lazy import
public/content/v1/ko/   미션 콘텐츠 JSON (버전 폴더로 마이그레이션 대비)
```

- **Phaser는 지도 배경·항로·비행기만.** 폭 600px 이하 compact 지도는 캔버스를 만들지 않고 DOM 목록으로 대체한다.
- **페이지 간 통신은 EventBus의 EventMap만.** 이벤트 이름 상수는 한 파일이 단일 소스.
- **도장 규칙은 `core/stamps.ts` 한 곳.** 여권 도장 6칸 = 6대륙(북·남아메리카 분리), 지구회의는 도장 대신 인증서.
- 중복이 생기면 공용 모듈로 올린다 — HTML 이스케이프 6벌→1, reducedMotion 판정 7벌→1, 가로 스와이프 2벌→1, 타이머 풀 2벌→1로 통합한 이력이 있다.

## 4. 데이터 안전 — 저장값을 믿지 않는다

- 키 `world_connection_journey.save.v1`. `validateSave()`가 필드 단위로 검증·복구하고 손상 원문은 백업 키에 남긴다.
- **해금 상태는 저장값의 unlocked를 신뢰하지 않고** 라우터가 이동할 때마다 `recomputeUnlocks()`로 다시 계산한다. localStorage를 손으로 고쳐도 잠금이 안 풀린다.
- 보상·도장은 `rewardClaimedById`로 1회만. 저장은 microtask로 병합, 실패하면 크래시 대신 토스트.
- 점수는 계산은 하되 화면에 표시하지 않기로 확정(2026-09-01). 경쟁보다 순환 완주를 보상하는 설계.
- 라우터 전환 가드: `isTransitioning` + 300ms 디바운스로 연속 클릭 중복 열림 방지.

## 5. 레이아웃 계약 — 전 페이지 공통 규칙

`docs/LAYOUT_CONTRACT.md`가 강제하는 4행 그리드:

```
.page (grid: auto / 1fr / auto / auto)
├─ .top-bar     뒤로·제목 리본·설정 (고정)
├─ .page-body   유일한 스크롤 영역 (min-height:0)
├─ .guide-wrap  마스코트 + 타이핑 말풍선 (겹침 불가)
└─ .bottom-bar  다음 행동 버튼 1개 (고정)
```

- 한 화면에 텍스트 블록 3개 이하. "지금 뭘 해야 하는지"는 가이드 말풍선, 항목 설명은 그림+한 줄, 근거는 모달.
- 페이지 안에서 `height`를 px로 고정하지 않는다. `min-height:0` + `flex:1` + 내부 스크롤.
- 타이포는 토큰만(`--fs-body` 20.5px, `--fs-small` 16px 하한). 제목·버튼은 Jua, 문장은 Pretendard. 한글은 어절 단위 줄바꿈(`word-break:keep-all`).
- 버튼 문구는 눌렀을 때 일어날 일을 2~12자로("카드 확인하기").

## 6. 반응형 — 실기 캡처로 배운 것 (2026-09-02~03)

전자칠판 1920×1080·웹앱 1366×768·태블릿 1280×800에서 시작해 폰 가로(915×412·844×390)·태블릿 가로 1024×600·폴드 가로로 넓혔다. 실기 캡처를 재현하며 얻은 규칙:

1. **실기 뷰포트를 먼저 잰다.** 갤럭시 폴드 가로는 CSS 뷰포트가 830×515였다(예상했던 974×601이 아님). 캡처 속 버튼 픽셀 크기로 역산해 맞췄다.
2. **세로 폰 규칙에 `orientation:portrait`를 붙인다.** `max-width:900px`만 걸면 폴드 가로에도 걸려 카드가 위아래로 쌓이며 납작해진다. 가로 낮은 창은 `(max-width:900px) and (max-height:560px)` 전용 블록으로.
3. **지도 핀 축소는 뷰포트가 아니라 지도 칸 컨테이너 쿼리 기준.** 높이 제한 때문에 지도 칸만 작아지는 경우를 뷰포트 폭으로는 못 잡는다.
4. **고정 px 아바타·토큰은 지도 폭 비율로 상한.** 500px 지도에 96px 원 다섯 개면 무조건 겹친다.
5. **제목 리본은 어느 폭에서든 1줄.** nowrap + 말줄임 + ResizeObserver 글자 축소, 웹폰트 로드 뒤 재측정(대체 글꼴 기준으로 재면 틀린다).
6. **`vh` 대신 `dvh`.** 폰 주소창이 보이면 vh 기준 배치가 넘친다.
7. **말풍선을 `pointer-events:none`으로 통과시키지 않는다.** 말풍선 안 버튼이 죽는다. 자리를 옮기는 게 답.
8. **배지는 모서리 밖으로, 카드는 내용만큼.** 완료 체크가 글자를 덮거나 3줄에서 잘리는 건 전부 고정 높이 + overflow hidden이 원인이었다.

## 7. 검증 자동화 — 사람 눈과 스크립트를 같이

- `scripts/qa-sweep.cjs`: Playwright로 44화면 × 7해상도(830×515·915×412·1024×600·1280×800·1366×768·1900×880·1920×1080)에 저장 상태를 심어 들어가 **글자 잘림·요소 겹침·화면 밖·작은 터치 영역·버튼 가려짐·페이지 스크롤**을 검출. 마감 시점 0건.
- `scripts/shot-vp.cjs`: 같은 장면 정의로 원하는 크기의 스크린샷을 찍어 PNG를 직접 본다. 자동 검사가 못 잡는 "글자가 배지에 가려짐"은 눈으로만 잡혔다.
- 스윕 오탐도 기록해 둔다(예: 스크롤 칸에 잘린 버튼을 '가려짐'으로 셈 → 예외 처리). 결과는 `docs/reviews/QA-SWEEP-<날짜>.md`.
- 단위 테스트 Vitest 21파일 98개: 저장 검증·복구, 해금 규칙, 보상 중복, 시뮬 계수, 대화 분기, 콘텐츠 스키마·학습목표 존재.
- 병렬 작업: 화면 영역별로 파일을 나눠 에이전트 4~6개를 동시에 돌리고, 공용 CSS는 한 에이전트만 손대게 했다. 같은 파일 동시 편집이 유일한 충돌 원인이었다.

## 8. 인증서 — 인쇄와 저장

- A4 세로 시트. 학교·학년반·번호·이름은 빈칸으로 두고 손으로 쓰게 했다(개인정보를 앱에 넣지 않음).
- 인쇄: `@media print`에서 조상은 남기고 형제만 숨긴다(조상을 숨기면 인증서까지 사라진다). `print-color-adjust:exact`.
- 이미지 저장: A4 폭 794px 시트를 html2canvas로 2배 PNG(1588×2246)로 굽는다. 터치 기기는 공유 시트(navigator.share)로 갤러리 저장·카톡 전송, PC는 다운로드. **공유 시트는 터치 직후에만 열리므로 화면 진입 때 미리 렌더**해 둔다. 렌더용 시트는 굽는 동안만 붙였다 떼어 인쇄 2장·검사 오탐을 막는다.
- 설치형(standalone) iOS처럼 인쇄 창이 안 뜨는 환경은 "이미지로 저장해서 갤러리에서 인쇄" 안내로 우회.

## 9. 에셋·성능

- 이미지는 원본 보존 후 WebP 변환(`scripts/build-assets.mjs`), semantic id → src 매니페스트로 참조. 안 쓰는 파일은 삭제 대신 `_unused/`로 이동.
- 자산 다이어트 75→43MB. BGM 6개 13.7MB는 미션 진입 때 스트리밍이라 첫 로딩과 무관(이미 64kbps라 더 줄이면 음질 손실 → 보류 결정).
- 학교 기기 FPS·학교 Wi-Fi 30명 동시 접속은 실측하지 않았다. 수치를 보장하지 않는다.
